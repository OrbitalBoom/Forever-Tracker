# Forever Tracker

A locally run companion site for a World of Warcraft character on **Forever** (Classic Era / vanilla, level cap 60, with room for the server’s extra content).

## How to open it

No server, no install, no internet required:

1. Open the `wow-forever` folder.
2. Double-click `index.html` (or open it in any modern browser).

Your character is saved automatically in this browser as you type — there is no Save button for that.

## Cloud save

To also keep a copy in this GitHub repository (so it comes back if the browser clears its storage, or if you open the site on another computer):

1. Click the **Cloud save** status in the header.
2. Create a [fine-grained personal access token](https://github.com/settings/personal-access-tokens/new). Name it something like “Forever Tracker”, and set a long expiration.
3. Under **Repository access**, choose **Only select repositories** and pick **Forever-Tracker**.
4. Under **Permissions**, set **Contents** to **Read and write**. Leave everything else as it is.
5. Generate the token, paste it into the Cloud save box, and click **Connect**.

After that, changes are written automatically (a few seconds after you edit, and when you leave the tab) to `save.json` on a dedicated `save-data` branch. That branch is never merged into `main`, so a save will not rebuild the site or clash with the weekly data refresh. The token stays in this browser only and is never written into `save.json` or an exported backup file.

A public copy of `save.json` can be read without a token, so a wiped browser can still restore your character. Connecting a token is only required to write updates. Because this repository is public, don’t put passwords or real-life personal information in your notes.

**Export JSON** / **Import JSON** are under Cloud save → Backup file, if you want a file on this computer.

## Tabs

- **Character** — name, race, class, spec, and level. Other tabs use this.
- **Goals** — Classic Era dungeons (Ragefire Chasm through Scholomance / Stratholme), raids through Naxxramas plus world bosses, notable mounts, and milestones. Add custom goals for Forever-specific content.
- **Gold** — three sub-tabs, **Gold Log**, **Farms**, and **AH Flips**, with the last one remembered in this browser. **Gold Log** is the gold log in g/s/c with a running total and chart. **Farms** is a **Gold Farming** list of community camps and routes (mob grinds, instance resets, gathering, cloth, and Auction House flips) for your level, ranked by gold per hour (live auction prices when we can compute them, otherwise a dated source snapshot), with simple type pills and favorites that save with the rest of your character. A farm whose creatures spawn inside an instance (checked from NorgannonDB spawn maps, not guessed) is tagged “Dungeon: &lt;name&gt;”; one checkbox, Hide dungeon farms, hides those and any raid or mixed-instance farms, and the list counts follow it. Gathering farms use the professions and skills you entered on the Professions tab (the same saved list). Each **mob grind** farm has a Spawn map button: it opens that zone’s map from the live Forever client (stitched `Interface/WorldMap` tiles, © Blizzard Entertainment; built via [wago.tools](https://wago.tools) the same way item and talent data are) with heat and hotspot markers at each listed mob’s spawn points. If a map image fails to load, a schematic grid of zone-map percentages is shown instead. Coordinates come from [NorgannonDB](https://github.com/zmarotrix/NorgannonDB) 1.9 (GPL-3.0; QuestieDB and CMaNGOS classic-db) and are relative to the official 1002×668 WorldMap frame. The map is labeled “Spawn locations from Classic data, may differ in Forever.” A mob with no recorded points shows “No spawn data”; nothing is guessed. Drop and reward names on each farm card (the compact loot line, the drop table, and the loot list) are hoverable on desktop and tappable on mobile: they open the same item tooltip used in Items & Upgrades, including live AH min buyout and usual (market) price, listed quantity and sold-per-day, the feed’s last-updated time, vendor sell price, a per-stack line when the Forever client says the item stacks, and a 7-day price trend when `data/price-history.js` is available. When the tooltip is opened from a farm card, it also shows that farm's drop rate per kill (and, if the camp lists several mobs, that the figure is a spawn- or equal-weighted average across them — per-mob rates are shown only when the farm data actually has them), expected kills per 1 drop, expected items per kill when a quantity range is stored, and expected drops per hour when the farm has a sourced kills/hour figure. Rates come from the existing farm loot data and are labeled “Classic drop data, may differ in Forever,” unless the rate itself is from a Forever-era guide. If a drop has no rate, the tooltip says “Drop rate unknown” and omits the kills line. Opening the same item outside a farm (for example in the Items DB) does not show this section. Keep the pointer on the same drop for about a second and a short bar along the top of the tooltip fills; when it finishes the tooltip locks in place (subtle gold glow and pin) so you can move onto it and click View in Items DB. Leave before the bar finishes and the tooltip hides as usual. Once locked it stays while the pointer is over the item or the tooltip, with a brief grace period for the gap between them; moving away from both, pressing Escape, or the close button dismisses it. Hovering a different item replaces it. A click or tap also pins the tooltip (with a close button), including on touch. The fill animation is simplified when the browser asks for reduced motion. Names are matched to item IDs from the existing item database (exact match after light normalization only); an unmatched name stays plain text and is never guessed. **AH Flips** is an **AH flip finder** for underpriced auction listings. Old `#gold` and `#farming` / `#gold-farms` links still work (`#gold` reopens the last Gold sub-tab, `#farming` and `#gold-farms` open Farms; `#gold-log` and `#gold-flips` open the other two). `#professions` opens the Professions tab.
- **Professions** — the professions you have and their skill (Classic cap 300), a crafting list with have/need materials, Auction House ROI, and the **Profession guide**. You add your professions and skill on this tab — that list is the only source. The guide shows only those professions (if you have two craft professions, you can switch between them), starts at your saved skill, marks earlier steps as done, highlights the current step, and shows what to craft next plus materials and estimated AH/vendor cost from here to the next milestone (75 / 150 / 225 / 300). Changing skill in the guide updates the saved profession skill (on change, not while you type). If no professions are listed, a short note points you to Add profession above. Gathering professions have no 1–300 craft guide here.
  - **Leveling guide 1–300** for Alchemy, Blacksmithing, Enchanting, Engineering, Leatherworking, Tailoring, Cooking, First Aid, and Mining (smelting). From your current skill it picks, for every skill point, the recipe with the lowest expected cost per point (orange 100%, then (grey − skill) / (grey − yellow) through yellow/green, 0 at grey), groups the points into steps with expected craft counts, and builds a shopping list (vendor vs AH), the bars/bolts/parts worth crafting yourself, and the recipes you must buy or find. Optimize for lowest gold cost (AH prices) or fewest raw materials; filter recipe sources (trainer, vendor, drop/quest, unknown); optionally subtract resale value. Step checkboxes save in the backup; **Lock this plan** freezes the steps so price changes don't reshuffle them. Recipes with a cooldown (transmutes, Mooncloth…) are never used for leveling. Recipe purchase prices are listed but not added to the step costs.
  - **Best profit by skill**: every recipe you can know at a chosen skill, with material cost, AH price (market and lowest), vendor sell price, profit per craft after the 5% AH cut, ROI %, units listed, and sold/day (when the source has it). Click any column to sort.
  - Works without prices (vendor prices and estimates, marked “est.”).
- **Notes & Journal** — dated adventure journal plus a searchable notes/guides pad.
- **Items & Upgrades** — a centered paper doll for equipped gear. Click a slot to see upgrades at your level (required level, and score vs. what’s equipped), with a short “Coming soon” list for the next 3 levels. The slot panel has simple type chips (Usable by the selected class, All, and the subtypes in the data — Bows, Guns, Wands, Cloth, and so on), a Best-for dropdown covering every spec of every class plus general roles, a Sort-by dropdown (Best for spec, Rarity, Item level, or Required level), and a Min rarity dropdown limited to qualities present in that slot. A class selector defaults to your saved character but lets you browse another class’s usable types and specs. Items are scored with the rough relative weights in `js/item-weights.js` (not sims); a “Good for X” tag explains which stats counted. Pieces with no stat data are listed after scored ones when sorting by spec, and marked “stats unknown.” Items whose only power is an on-use or equip effect are marked “Effect only” and listed after scored upgrades, with the effect text on the card. A “Set what I’m wearing” search in the slot panel finds any item for that slot (any level, type, class, rarity, including Classic-reference items that are not Forever-verified) and can equip it, with a small warning if your class does not normally use it. Search also matches names like “cloak of the monkey,” and is tolerant of apostrophes, punctuation, and close typoes (so “humbers helm” finds Humbert’s Helm). Items that can roll a Classic random suffix show “Random enchant: N options” and a dropdown of exact stats (from SpellItemEnchantment); the equipped piece stores the chosen suffix, tooltips show the full name and suffix stats in green, upgrade lists score each item by its best possible suffix for the selected spec, and auction prices are the base item’s price unless a per-suffix feed is present (the current feed is not). Suffix tables live in `data/items/suffixes.js` and load only when the Items tab needs them. The piece you have equipped is pinned at the top of the panel. Filter and sort choices are saved per slot and apply only to the upgrade list. Hover any item (paper doll, upgrade list, item database, profession reagents, or gold-farm loot) for a Classic-style tooltip built from our item data — not Wowhead’s script. The tooltip follows the cursor until you keep the pointer on the same item for about a second; a short bar along the top fills during that wait, then the tooltip locks so you can move onto it and click links such as View in Items DB. Leaving early cancels the lock. Once locked it stays while the pointer is over the item or the tooltip (with a short grace delay across the gap); Escape, the close button, or moving away from both closes it, and hovering a different item replaces it. A click or tap still pins it, including on touch, and the timer animation is simplified when reduced motion is requested. Hold Shift to compare with the item already in that slot. The item database (search, uses, drop/vendor/craft/quest sources, live US Normal Horde auction prices) sits below, collapsed. Custom items in your save still work.
- **Leveling Route** — hand-picked paths from level 1 to 60 for every race and both factions (default Undead Horde, following the Character tab when “Follow character race” is on). Pick a **route source** and a **variant**:
  - **Combined (default):** current public [RestedXP](https://github.com/RestedXP/RXPGuides) Forever Speedrun or Dungeon Guide through about 21 (Alliance) or 22 (Horde), then [OpenXP](https://github.com/mjared123/OpenXP)’s 21–60 community route. Each author’s order is kept. Combined also inserts optional **Forever Tracker add-on** chapters (auto-optimized, not RestedXP/OpenXP) for Riverglades (35–45, both factions), Shen’dralas (38–45, Horde plus a fuller Alliance path than OpenXP’s 40–41 stub), and Mount Hyjal (55–60, both factions). The **Include new zones** toggle is on by default; OpenXP chapters in those level bands are left in place and can be skipped with **Skip overlapping OpenXP chapters**.
  - **RestedXP free:** only the public Forever chapters (they end ~21–22; later RestedXP chapters are paid and are not included).
  - **OpenXP 1–60:** OpenXP’s own files, including its copies of the early RestedXP chapters (those copies lag the current RestedXP repo) plus OpenXP 21–60.
  - **Variants:** Speedrun, Dungeon Guide (RestedXP dungeon chapters 1–22, then OpenXP overworld; OpenXP’s standalone dungeon quest lists are shown separately). Mages also get **Mage AoE (RestedXP)** where those public files exist.

  Each step has a checkbox, skip, and notes. Progress is stored per character (name + race + source + variant) in the same localStorage backup. You can hide completed steps and jump to the current one. Coordinates come from the guide files (percentages, or world coordinates converted with Blizzard’s classic map bounds) and are labeled as such. No quest or coordinate is invented. The previous “every eligible quest” auto-route was replaced; old checkboxes are reset once so they don’t point at the wrong steps.
- **Talents** — WoW: Forever talent calculator (467 talents, build 1.60.1.70938). First point at 10, 51 at 60; milestone talents at 11 / 16 / 21 / 31 points. Dual Specialization at level 40 (Primary / Secondary). Published leveling builds load with one click and cite their guide and date. A **Community builds** list adds Talents Forever popular, tagged, and level-30 builds (source, author, link out, class/role filters, sort by popularity or newest). Each spec also has a derived **Community consensus** path and an optional pick-rate **heat map** on the trees (sample sizes are labelled and never padded). Once a build is loaded, a level bar lets you step from 10 to 60 (slider, ±1, and jumps to your level, +1/+2/+3/+5, or 60) without changing your character’s saved level. A callout names the talent gained at the viewed level, the next five levels appear as jump chips, and the tree highlights the new point (plus any upcoming points when you preview ahead). A **Classic Era (reference)** toggle shows the old 1.12 trees for comparison only.

### Known gaps (flagged, not reordered)

- Riverglades, Shen’dralas (Horde, and Alliance quests beyond OpenXP’s short 40–41 stub), and Mount Hyjal are not in the imported RestedXP or OpenXP routes. Combined adds optional Forever Tracker add-on chapters for them. Those chapters are auto-optimized from local catalog data (nearest-neighbor / hub batching on pickup coordinates), not author-written guides.
- forever-quests and ForeverDB have no records for these new zones. Prerequisites, exclusiveTo, and turn-in NPCs/coordinates now come from NorgannonDB where it lists them; the walking order waits on a prerequisite when both quests are in the same chapter. Zephras `data-also=chain` tags were too loose to treat as a prerequisite graph and were not used as chains.
- Quests whose giver stands outside the zone (for example breadcrumbs from Undercity or Stormwind) are listed first in their level band with the giver’s real zone and coordinates, and are left out of the in-zone walking optimization. Placeholder entries (“REUSE ME”) are dropped.
- Many catalog entries have no faction tag (especially Shen’dralas and Mount Hyjal) or no coordinates; those steps are marked **unverified** and listed at the end of the chapter as optional. NorgannonDB has no race restriction on them either, and the giver’s NPC reaction was not used to guess a side (it disagrees with Zephras’ tags too often).
- Objective coordinates are not shown — only pickup/giver points, turn-in points where NorgannonDB has them, and the published flight points (Rog'mar, Farholde Keep, Summit of Eternity, Tainted Foothills). Shen’dralas has no recorded flight point.
- Zephras Isle is covered in the Skyborne 1–9 and 9–13 / 9–12 RestedXP chapters.
- LevelForge 1–60 community chains were not imported: the LevelForge addon is MIT, but guide authors keep their rights and there is no clear redistribution license for bundling those routes here.

**Auction prices** (`data/prices.json`, plus `data/prices.js` so the page also works from `file://`). The fetcher pulls the **full** US Normal Horde house dump (Blizzard: one request for auctions plus one for commodities; Forever Goblin: one `/api/m/us-114/prices` request) and keeps every priced auction — not a profession-only id list. Compact schema 2: each id maps to `[minBuyout, marketValue, quantity, soldPerDay?]`. The page also still reads the older schema 1 object shape. `marketValue` is the average of the cheapest 15% of units listed; `soldPerDay` is Forever Goblin only and is omitted when unknown. Copper per single item. House 114.

- **Official source:** Blizzard Battle.net Game Data API, `dynamic-forever-us` namespace: `/data/wow/ruleset/2/auctions/114` and `/data/wow/ruleset/2/auctions/114/commodities` (WoW: Forever uses rulesets instead of realms; ruleset 2 = Normal). Blizzard publishes a new snapshot about once an hour. Used under the [Blizzard Developer API Terms of Use](https://www.blizzard.com/en-us/legal/a2989b50-5f16-43b1-abec-2ae17cc09dd6/blizzard-developer-api-terms-of-use). Needs a free API client (see below).
- **Fallback while no API client is set up:** [Forever Goblin](https://forevergoblin.trade/about), a free fan site that stores the same hourly Blizzard API snapshots for every Forever auction house. Its robots.txt allows all crawling and it has no terms restricting reuse; the tracker makes one small request every 3 hours. The bundled snapshot in `data/prices.json` came from here (US Normal Horde, Nov 17, 2026 23:25 UTC). To turn the fallback off, add a repository variable `PRICE_FALLBACK` = `off`.
- **Auto-refresh:** `.github/workflows/prices.yml` runs every hour (every 3 hours on the fallback), runs `tools/prices/fetch_prices.py`, and force-pushes `prices.json`/`prices.js` as a single commit to the **`prices-data`** branch, so `main`'s history doesn't grow and Pages doesn't redeploy. The branch itself is still force-pushed (no git history of past snapshots). The same job also merges a compact **7-day marketValue history** into `price-history.json` / `price-history.js` on that branch, unioning the previous `prices-data` window with the copy already on `main` and the new snapshot; a history-merge failure still publishes `prices.json`. The site loads `https://raw.githubusercontent.com/<owner>/<repo>/prices-data/prices.json` (and `price-history.json` on the Gold tab). For prices it uses whichever file is newer; for the flip-finder history it unions the live `prices-data` file with the copy bundled in `main` by sample timestamp (the newest value wins when two samples share a time, and samples older than the 7-day window are dropped), so a short live file cannot replace the bundled window. It also runs once when the workflow or the price script changes, and can be run by hand from the Actions tab (“Refresh auction prices” → Run workflow).
- **Set up the official API (optional, recommended):** sign in at <https://develop.battle.net/access/clients> with your Battle.net account → **Create Client** (any name, e.g. “Forever Tracker”; redirect URL can be left blank or `https://localhost`; tick “I do not have a service URL”; intended use: personal price tracker) → copy the **Client ID** and **Client Secret**. Then in GitHub: repo **Settings → Secrets and variables → Actions → New repository secret**: `BLIZZARD_CLIENT_ID` and `BLIZZARD_CLIENT_SECRET`. The next run uses Blizzard directly.
- Note: GitHub pauses scheduled workflows in a public repo after 60 days with no commits; the weekly data refresh keeps the repo active.

When doing the Wednesday refresh, also re-run `tools/items/build_items.py` (see `tools/items/README.md`) so the item database picks up new Forever client builds and NorgannonDB updates.
When doing the Wednesday refresh, also re-run `python3 tools/talent-tooltips/build_talent_tooltips.py` (see `tools/talent-tooltips/README.md`) so talent tooltips stay in sync with the live Forever client DB2, then bump `?v=`.

**AH flip finder** (Gold tab → **AH Flips** sub-tab, `js/ah-flips.js`): lists auction-house items whose cheapest buyout is under their usual price, so you can buy and resell them. Usual price is the 7-day median of `marketValue` (the average of the cheapest 15% of units listed) from the rolling `data/price-history.json` window maintained by the price workflow. If history has not loaded yet, the UI falls back to the current `marketValue` and says so. Profit is after the 5% auction-house cut and, when vendor sell is known, a Classic 12-hour deposit (5% of vendor sell). Items a vendor sells for at or below the auction buyout are omitted; items you can sell to a vendor for more than the buyout are flagged “vendor flip.” Filters cover minimum profit, minimum sold/day, a budget cap, category, and hiding thin listings (few copies listed or under 1 sold/day). Sort by profit, discount, or profit × sold/day. The “as of” time is shown in America/New_York. Sold/day comes from the Forever Goblin field in the price feed and is shown as unknown when absent — numbers are never invented. The history and vendor maps are loaded only when the Gold tab opens. Refresh vendor data with `python3 tools/prices/build_item_vendor.py` after an item-database rebuild.

**Gold farming spots** (`js/gold-farms-data.js`): community camps and routes for WoW: Forever, with source URLs and dates on every entry. When doing the weekly refresh, re-check the principal sources listed in the file header (Conquest Capped, forevergold.dad, FrostyBoost, boosting.pro, Wowhead Forever profession overviews, ByteTavern, theforeverguides, botwowforever, Warcraft Tavern, warcraftmaps, r/wowforever), update sourced prices and dates, add or retire spots the community has confirmed or abandoned, and keep the exclusion list current. Prefer recent Forever posts over Classic-era guides. Tag each spot `forever` (priced or described for live Forever) or `classic` (Classic Era / beta, likely still applies — the UI labels it that way). Do not invent camps, drop rates, or gold-per-hour figures; only store numbers a source states, or let the UI compute a live value from `data/prices.js` / the `prices-data` branch. Leave out bug exploits, duplication, geometry glitches, and anything that violates Blizzard’s terms of use. Flag anything borderline as commonly hotfixed or nerfed, and leave it out if it is an actual exploit.

## Other data sources

- **Item database** (`data/items/`, built by `tools/items/build_items.py` — see `tools/items/README.md` for the Wednesday refresh). Forever-confirmed facts come from the live client via [wago.tools](https://wago.tools) DB2 `ItemSparse`/`Item` (name, quality, item level, required level, slot, vendor buy/sell, icon file id) and from [zmarotrix/NorgannonDB](https://github.com/zmarotrix/NorgannonDB) (GPL-3.0; drops with chances, vendors, quest uses and rewards, recipes), merged with this repo's Forever profession data (LibProfessionDB). Numeric gear stats and weapon damage prefer Classic-reference values from the public [Napalmsteak/WoW-Classic-Item-Caches](https://github.com/Napalmsteak/WoW-Classic-Item-Caches) Wowhead Classic tooltips and from [cmangos/classic-db](https://github.com/cmangos/classic-db) `item_template` (GPL-3.0) when those sources have numbers. Forever-new items, and Classic items the tooltip/DB cache missed, get amounts derived from the live client DB2 on [wago.tools](https://wago.tools) (build 1.60.1.71037): `ItemSparse` `StatModifier_bonusStat` × `StatPercentEditor` against `RandPropPoints` (Good/Superior/Epic column by quality, slot index by `InventoryType`), plus `ItemDamageOneHand` / `ItemDamageTwoHand` and `ItemArmorTotal` × `ItemArmorQuality` × `ArmorLocation` (or `ItemArmorShield`). Rating types are converted to percents with the TBC level-60 coefficients the Forever tooltip uses (crit 14, hit 10, dodge 12, parry 15, block 5, spell hit 8). These are tagged `statSource: forever-client-derived` and the tooltip notes “Stats calculated from Forever game data.” Classic numbers are kept when both exist, even if the Forever allocation differs. The formula was checked against Classic amounts on overlapping ItemSparse items (~97% exact) and against live [Wowhelm](https://www.wowhelm.com) Forever tooltips (stats and melee/ranged weapon ranges). Items that appear only in Classic sources (no `ItemSparse` row in the live client) are marked Classic-reference and are omitted from the upgrade finder. Auction prices come from the existing `prices-data` feed, not from this build. Do not invent stats, drop rates, or prices.
- Forever talents: [Zephras](https://zephras.com/data/) JSON export of the WoW Forever client Trait tables, build 1.60.1.70938 (hotfix cache applied), CC BY 4.0. Credit: "Talent data: Zephras (https://zephras.com), CC BY 4.0." Game names and texts © Blizzard Entertainment. - **Talent tooltips** (`js/talent-tooltips-data.js`, built by `tools/talent-tooltips/build_talent_tooltips.py`): hovering a talent on the Talents tab (or long-pressing on touch) shows a Classic-style tooltip with the talent name, rank, required points and prerequisite, and the actual client description with `$tokens` filled in at the selected character or preview level (default: your character’s level). If the talent grants an ability (for example Intimidation or Bestial Wrath), the tooltip also shows cost, range, cast time, and cooldown. Numbers come from the live Forever client DB2 on [wago.tools](https://wago.tools) (build 1.60.1.71037 or newer): each calculator talent is mapped through TraitNode → TraitDefinition → Spell, and per-rank values come from TraitDefinitionEffectPoints / CurvePoint when present, otherwise SpellEffect (plus EffectRealPointsPerLevel for spells that scale with level). Talent / TalentTab tables in this build are leftover Classic data and are not used. The precomputed file is loaded only when the Talents tab opens, so the rest of the calculator stays fast; saved talent ranks are unchanged. A token that cannot be resolved (for example `$rap` or `$ap`, which need character attack power) is left in the raw text with a short note — numbers are never invented. When doing the Wednesday refresh, re-run `python3 tools/talent-tooltips/build_talent_tooltips.py` from the repo root (optional `--cache-dir`) and bump `?v=`.
- **Community builds** (`js/community-builds.js`, rebuilt by `tools/community-builds/refresh_community_builds.py`): popular, tagged (Leveling / PvE / PvP), and level-30 listings from [Talents Forever](https://talentsforever.com) (robots.txt allows these pages; terms welcome sharing calculator links and forbid hammering the site). Popularity is that site’s first-party tally of share, save, and link opens, or leveling-order counts, with no identities. Talent / racial data there is CC BY 4.0; credit “Data from talentsforever.com (https://talentsforever.com).” Calculator URLs are decoded against the Zephras Forever trees in `js/talents.js` and only legal allocations are kept. A build is assigned to a spec by the tree with the most points; the card says whether that matches the source’s own label or was inferred. The Talents tab lists them in a **Community builds** section (class filter, role filter, sort by popularity or newest) next to the published Timesaver presets, with a source/author label and a link out. Do not scrape or republish the [wow-forever.gg](https://wow-forever.gg) catalog — that site reserves its builds, pick rates, and datasets, and disallows `/api/`. Linking out to it is fine.
- **Community heat map and consensus** (same file and script): for each spec of each class, the refresh takes up to the 50 most popular valid community builds (never padded; the real count is stored and shown). The talent trees can show a pick-rate heat map for the current spec (percent of eligible builds that take the talent, average rank, and — only from builds that publish a point order — the level when it is first picked). A separate **Community consensus** card per spec, labelled “Community consensus (N builds),” is a 51-point path filled level by level with the talent the most of those 51-point builds take next, staying inside Forever tier and prerequisite rules. It is kept apart from published guides and from the individual community listings. When doing the Wednesday refresh, re-run `python3 tools/community-builds/refresh_community_builds.py` from the repo root (optional `--cache-dir` to reuse listing HTML). The script fetches only the nine class `/builds` pages plus `/popular` and `/level-30`, with a short delay; do not mass-download individual calculator pages.
